# M16 Fab Enterprise Digital Twin v7.0

합성 반도체 공정 모델을 사용하는 로컬 디지털 트윈입니다. 대시보드에서
설비 상태와 FOUP 흐름을 보고, 규칙 기반 제어의 효과를 A/B 벤치마크로 비교합니다.

## 실행

Python 3.11 이상에서 실행합니다.

```bash
python -m pip install -r requirements.txt
uvicorn backend.main:app --reload
```

또는 Docker Compose로 실행합니다.

```bash
docker compose up --build -d
```

- 관리자 대시보드 http://localhost:8000/
- Swagger REST API http://localhost:8000/docs
- SQLite 기본 경로 `data/m16_fab_v7.db`. Compose는 `./data`를 마운트합니다.
- 외부 PostgreSQL을 쓰려면 `DATABASE_URL`을 `postgresql+psycopg://...`로 설정합니다.
- 개발 테스트는 프로젝트 루트에서 `python -m pytest -q`로 실행합니다.

사내 TLS 검사 환경에서는 신뢰할 수 있는 CA 번들을 Docker 빌드의
`pip_ca` BuildKit secret으로 전달할 수 있습니다.

## 기능과 운용 범위

- **실시간 텔레메트리** — `/ws/fab/live`에 구독자가 있고 Live 모드가 켜져 있으면
  2초마다 가상 팹 시간 15분을 진행합니다. 틱과 의사결정은 DB에 저장됩니다.
  SQLite 체크포인트에 진행 중 Lot, 설비, 난수와 승인 대기 제안을 함께 기록합니다.
  서버는 재시작 시 같은 상태를 복원합니다. 한 DB에 단일 Uvicorn 워커로 실행합니다.
- **폐루프 제어** — Auto-Pilot은 RUL·FDC·OHT·Q-Time 규칙으로 PM 또는 감속을
  적용합니다. HITL은 관리자가 승인할 때 적용하고 승인자를 DB에 기록합니다.
  두 공급자 키를 설정하면 의견 생성에만 OpenAI·Gemini를 사용합니다.
  실행 제어와 A/B 벤치마크는 결정론적 규칙을 사용합니다.
- **로그인과 권한** — 기본 로컬 시연은 직무 헤더를 사용합니다. 운영자 파일을
  설정하면 비밀번호와 서버 세션이 필요하고 직무 헤더는 권한에 영향을 주지 않습니다.
- **A/B 벤치마크** — 단일 시드 비교와 다중 시드 분석을 제공합니다. 아래 검증 절에
  합성 기준, 비교 지표와 모의 납기 기준을 설명합니다.

## 3D 설비 보기

8개 설비는 공정별 대표 구조를 바탕으로 모델링했습니다. 설비 이름과 상태등으로
구분할 수 있고, 개별 부품을 클릭하면 해당 설비의 계측과 제어 화면이 열립니다.
`선택 설비 확대`로 구조를 확인하고 `전체 보기`로 복귀할 수 있습니다.
상단의 `설비 제어`와 `AI 제어` 버튼은 기본 접힘 상태이며, 필요할 때 각각
3D 화면 아래에 패널을 엽니다. 클린룸 절개도에는 설비 베이, 작업 통로, 에어록,
FOUP 스토커와 천장 OHT 레일이 있습니다. 이송 이벤트는 레일과 로드포트를
따라 재생됩니다.
모델은 실제 M16 CAD나 제조사 치수에 기반한 복제본이 아닙니다.


## Lot 투입과 공정 산출 이력

**3D 실시간 관제·제어** 화면 아래에서 웨이퍼 1~25매를 FOUP 한 개에 넣고
일반·긴급 우선순위로 투입할 수 있습니다. 자동 투입은 25매이며 이미 진행 중인
초기 재공과 별도로 집계합니다. 공정 중인 설비에는 Lot·FOUP ID, 공정명, 수량,
진행률이 표시됩니다. 3D 반송은 기록된 이송 이벤트를 짧게 재생합니다.

Lot 이력에는 다음 정보가 남습니다.

- 투입 수량, Lot·FOUP ID, 우선순위와 스토커
- 출발지·로드포트, OHT 소요 시간·혼잡도, 대기시간·Q-Time 초과
- 공정별 투입·산출 수량, 처리시간, 온도 전후, 압력·RF, 목표·예측 CD,
  FDC T²·APC 오프셋, 다음 공정. 중단 시 재대기 수량과 재시도 횟수
- EDS 완료 후 양품 스토커와 QA 보류로 분류된 수량, 모델 다이 수율,
  총 경과 시간, Q-Time 초과 건수

중간 공정은 동일한 웨이퍼 수를 다음 공정으로 넘깁니다. 모의 EDS는 웨이퍼별
다이 100개의 합격 여부를 계산하고 양품 다이 92개 이상이면 해당 웨이퍼를 합격
처리합니다. 웨이퍼별 양품 다이 수와 검사 기준은 Lot 이력에 남습니다. 이 조건은
가상의 검사 기준입니다.

서버는 이력을 `lot_trace_events` 테이블에 저장합니다. 현재 실행 이력은
`GET /api/fab/lot-events`에서 조회하고, `lot_id`로 검색할 수 있습니다.
서버 재시작 후 이전 실행은 `trace_id`를 함께 지정해 조회합니다.
`POST /api/fab/lots`에는 예를 들어 `{"wafers":17,"priority":"HOT_LOT"}`를 보내며,
`engineer` 또는 `manager` 역할이 필요합니다.


## 검증 기준과 운용 가정

```bash
python -m backend.validation
python -m pytest -q tests
```

`validation/hbm3e_reference.json`은 25매 단일 Lot의 12개 단계별 처리시간,
대기시간과 완료 시각을 별도로 명시합니다. 기준 시나리오는 자동 투입과 무작위
고장을 끄고 선언된 공정 시간과 OHT 경로 시간을 대조합니다. 기준 데이터는 분석식으로
작성한 합성 값입니다. 현장 검증에는 장비별 처리·대기시간, 검사 기준 및 실측 다이
데이터가 필요합니다.

OHT는 가용 대차와 공유 레일 구간을 시간순으로 예약합니다. 목적지 스토커 슬롯을
미리 확보할 수 없거나 로드포트가 사용 중이면 Lot이 대기합니다. 기본 거리와 슬롯은
합성 설정입니다. OHT 일정은 15분 틱 안에서 배차하고, 틱을 넘는 배차는 다음 틱으로
미룹니다. 3D 레일은 관제용 배치입니다.

다중 시드 API는 `POST /api/fab/benchmark-study`에서 동일한 초기 시드들을
Baseline과 Auto-Pilot에 각각 적용합니다. 신규 투입 Lot에 가상 납기 480분을
부여하고, 실험 종료 전에 납기가 도래한 Lot만 정시 완료율 계산에 포함합니다.
미완료 Lot도 납기가 지났다면 분모에 포함됩니다. 양품당 원가는 기존 모델 단위원가를
합격 웨이퍼 수량으로 환산한 비교 지표입니다. 분모가 0인 지표는 결측으로 남기며,
평균 차이와 시드별 최솟값·최댓값은 두 시나리오의 값이 모두 있는 시드만 비교합니다.

### 운영자 계정 활성화

`python -m backend.auth`를 실행해 비밀번호 해시를 만든 뒤, 저장소 외부의 접근 제한
JSON 파일에 계정을 등록합니다. 예시는 다음과 같습니다.

```json
{
  "ENG-01": {"role": "engineer", "password_hash": "<출력된 해시>"}
}
```

직무는 `engineer`, `maintenance`, `manager` 중 하나입니다. 서버 실행 전에
`M16_OPERATOR_FILE`에 JSON 절대 경로를 지정합니다. Docker에서 사용하려면 해당 파일을
읽기 전용으로 마운트하고 컨테이너 안 경로를 해당 환경 변수에 지정합니다.
HTTPS 배포에서는 `M16_SECURE_COOKIE=1`을 설정합니다. 운영 모드에서 API와
WebSocket은 로그인 세션을 검증합니다. 현장 운영에는 조직 SSO, TLS, 접근 및
백업 정책을 현장 기준에 맞춰 추가해야 합니다.
